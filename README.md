# Plugged: EV Charging Finder

An EV charging hub finder. It lists the nearest hubs to the user and shows how many spots are free at each one, updating live. A small Express + TypeScript backend serves the data (seeded stub data for now) and streams availability changes to the browser.

## Stack

- **Backend**: Node 20+, Express 5, TypeScript. In-memory store, REST API, Server-Sent Events.
- **Frontend**: single HTML page, Tailwind CSS (CDN), a little plain CSS for motion, TypeScript compiled to ES modules (no bundler).

## Run it (VS Code)

1. Open the `ev-charging-finder` folder in VS Code (File > Open Folder).
2. Open the integrated terminal and run:

```bash
npm install     # one install at the root covers both folders
npm run build   # compiles frontend and backend
npm start       # http://localhost:3000   (set PORT to change it)
```

`npm run dev` builds and starts in one step. Open http://localhost:3000. The backend hosts the frontend itself, so there is no CORS setup.

While editing, run `npm run watch -w frontend` and `npm run watch -w backend` in two terminals to recompile on save (restart the server after backend changes).

## API

| Endpoint | Description |
| --- | --- |
| `GET /api/hubs` | List hubs. Query: `lat`, `lng` (together; adds `distanceKm` and sorts nearest-first), `radiusKm`, `available=true`, `minPowerKw`, `q`, `limit` (1-100). Without a location, hubs are sorted by name and `distanceKm` is `null`. |
| `GET /api/hubs/:id` | One hub, with `distanceKm` if `lat` and `lng` are given. 404 if unknown. |
| `GET /api/events` | Server-Sent Events. Sends a `snapshot` event on connect, then an `availability` event whenever a hub's free-spot count changes. |
| `GET /api/health` | Liveness check. |

Invalid input returns `400` with `{ "error": "..." }`.

```bash
curl "http://localhost:3000/api/hubs?lat=19.076&lng=72.8777&limit=3"
curl -N http://localhost:3000/api/events
```

## How it works

- **Nearest first**: the browser sends its location (or a default one until you click "Use my location"), the server computes haversine distances and returns hubs nearest-first. Choosing a new location refetches.
- **Live spots**: the browser opens one `EventSource` connection. Updates patch the in-memory state and the cards re-render without a flash. If the connection drops, the browser reconnects on its own and the next `snapshot` brings every count back up to date. The header dot shows live (green) or reconnecting (grey).
- **Reactive frontend**: `store.set(patch)` merges state and re-renders. Filters, search, location, loading/error states and live updates all go through it.
- **Simulation**: `HubStore.startSimulation()` nudges one random hub's free spots every 4 seconds so the UI has something to show.

## Going to production

- Replace the seed data and in-memory `HubStore` internals in `backend/src/store.ts` with a database or a charger-network feed. Call `setAvailability(id, n)` whenever real occupancy changes and the SSE stream will push it to every client.
- Remove the `startSimulation()` call in `backend/src/index.ts`.
- For multiple server instances, fan availability changes out through a shared channel (for example Redis pub/sub) so every instance's SSE clients stay in sync.
